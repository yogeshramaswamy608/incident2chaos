# Second-model label check, plan (committed before any call that counts)

Written Mon Nov 23, 2026. Study: paper 1, "Do Chaos Experiments Match Real Cloud Incidents?" (dataset version 1.0.2).

Question. Do the released labels depend on the model that proposed them? A model from a second vendor (OpenAI) labels the reports again from codebook version 2 and the report text alone. It never sees a released label, an evidence note, the author's blind labels or the pilot verdicts.

Sample. Every report of corpus.csv (497) whose source's terms and robots.txt, read on the day of the run, allow an automated read for an AI system. Read Mon Nov 23, 2026: robots.txt of github.blog, status.cloud.google.com and aws.amazon.com (no rule covers /message/) allow all agents; azure.status.microsoft has no robots.txt (HTTP 404). blog.cloudflare.com now allows all agents and states "Content-Signal: ai-input=yes", but Cloudflare's website terms (section 8, read Nov 16, 2026) bar automated access for operating an AI system unless robots.txt allows it; until that is ruled, its 42 reports are left out (run.json "exclude_sources") and named in the paper. The terms pages of the other four sources are read again before the full pass.

Model and settings. A pilot of 10 reports (fixed seed, spread over the sources) on the two strongest text models listed on OpenAI's pricing page that day measures the cost of one report on each. The model is the stronger one whose full pass costs at most $20.00. Its exact model id and snapshot, reasoning effort, service tier and the prices read that day are written in run.json and in an addendum to this file before the full pass. What is left, up to $30.00 in all, buys a second pass of the same model, the 45 blind-sample reports first, for run-to-run agreement. The credit is $32.00 with no payment method, so spending cannot pass it.

Prompt. prompt.md (committed, sha256 logged with every call): codebook sections 1 to 3 and 6, then the report's title, date and text as fetched. Structured output: in scope, primary and secondary trigger, every fault class, primary fault class, confidence. Injectability is never asked of the model; it is derived from the primary fault class by incident2chaos.codebook.injectability, as for the released labels.

Measures, computed by analyze.py against the label set that is final after the paper 1 package ruling (pack 5), which may recode the 50 pilot reports: percent agreement and Cohen's kappa for the primary trigger, the primary fault class and injectability; the headline coverage figure (share of in-scope reports with a stated primary fault whose class is A, with its 95 percent Wilson interval) recomputed from the second model's labels beside the released figure; run-to-run agreement on the reports labelled twice. Disagreements are counted and reported. A valid run is reported whatever it shows. No released label changes because of this run.

Log. Every call: model, snapshot returned, date, prompt template sha256, the fetched text's URL, fetch time, length and sha256, the reply, tokens and cost. The report text itself is not committed, since the dataset redistributes no report text (site_terms.md); it is re-fetched from the logged URL. The paper states the fetch dates and how many reports opened.

Safety. The workflow runs only on a push to the branch gpt-label-check that changes gpt_check/run.json, never on pull_request_target; the key lives only in the repository secret OPENAI_API_KEY; requests are sent with store=false; every stage stops before a call that would take total spending past its cap.
